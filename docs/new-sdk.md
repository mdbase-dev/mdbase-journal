# Public SDK application intake

Journal consumes the immutable SDK4b dev packet through ordinary local file dependencies. This is development intake, not release/runtime qualification.

- SDK source: `4b9553819ddb769ff1487170c05494321d23ab8b`.
- Original SDK: 4,292,587 bytes, SHA-256 `9874074d6a68287780de2092a069c1cb4e81d3558e432b719b7525974eb6b0ad`.
- Original SDK SRI and independent active protocol pin: `vendor/mdbase-sdk-dev-4b955381.json`. The active protocol is the original `3c14fc913a8066a23f889e38559c9bb5ff7422e4` packet, not the retained older protocol archives.
- `MdbaseConnect`, `MdbaseApplicationDeclaration` and `MdbaseApplicationEntry` come from `@mdbase-dev/sdk`.
- Test-only `createApplicationFixture` and `MemoryReplica` come from `@mdbase-dev/sdk/testing`; the production entry never imports testing.
- The live public `MdbaseConnect` singleton owns lifecycle, `application()` and `connection(id)`. `snapshot.selection` distinguishes a requested collection from an actually usable one; an unapproved request cannot borrow an old ready connection.
- Approval, access review and the chooser invoke SDK `approve()`, `reauthorize()` and `chooseAnother()` directly in the gesture stack, preserving the original caller signal. No app-side selection URL parser, popup callback, raw installation bootstrap or missing-runtime workaround remains.
- Records use the same public `connection.records`, original create mutation/UUID, receipt/readback and shared record sessions. Files use that client's identical public FilesApi.

The build verifies the immutable archives and every installed SDK dist member against its original archive. It consumer-bundles only the built public ESM entry, retains the original same-artifact Worker beside it and preserves the packaged native module directory. SDK4b contains the original canonical runtime/SQLite WASM and default-expiry LAB trust. Its packet metadata reports `native.available=true`; this means asset availability only, not browser/native readiness, application registration or LAB admission. LAB native consumer builds work with explicit build inputs and preserve the original Worker/WASM bytes; production trust remains unavailable. The runtime remains independently sourced at `c5cb3a99f74a5cf56e48662060b8d8e76fc2e398` (3,533,579 bytes; SHA `38ca6f006aef7675ebe16abb981c7ba59fe0c27c287d78ee0b845c26aff37ba8`). Its actual native type-pack dispatch reaches provision validation; this does not prove durable pack application. Later phase-2 resource review/adoption changes are not qualified by this packet. Native source and SDK source remain distinct. The SDK's normal module-relative Worker/WASM/SQLite layout is preserved, including its literal asset references; Journal adds no bundler workaround. It does not rebuild, repack, rewrite installed declarations, renew trust or inject callbacks. Native/SQLite assets are integrity-pinned, not separately signed. The normal SDK producer bundles its existing pinned protocol dependency, so a fresh install root and empty npm cache can resolve it without installed metadata or app-specific dependency workarounds. The active original protocol archive remains byte-identical. This exact development packet retains an unreferenced historical `vendor/mdbase-dev-connect-protocol-0.1.0-beta.129.tgz` with SHA `dfc5db0daf6700874aa2c6235b86570f1d4e444740d0925bf1f97551cf43d3bd`; it is not the installed dependency or runtime protocol. That named-file/hash warning is specific to this dev packet and does not apply to a successor.

`npm run build` requires explicit registered application ID, environment and approved origin; see [README](../README.md). `npm run build:local` is an explicit writing-only build with no application constructor. Registration/native admission and deployment remain separate. The earlier SDK archive and provenance remain unchanged.

`npm run verify` checks strict declarations with `exactOptionalPropertyTypes=true`, `noUncheckedIndexedAccess=true`, `skipLibCheck=false`, public fixture/actual SDK records and files, browser-asset byte pins, and the writing-only build. Fixtures prove controlled app behavior, not physical popup/native lifecycle or real catalog readiness. The baseline prototype tests were replaced with typed tests of the new surface, not kept as a second app auth/data engine.

Earlier prototype drafts remain in their original storage namespace and are counted in settings. They are not automatically replayed without their original native identities. Failed local persistence never authorizes capture or clearing RAM text; uncertain native creation only checks the original receipt and record.
