# Public SDK application intake

Journal consumes the immutable SDK4c dev packet through ordinary local file dependencies. This is development intake, not release/runtime qualification.

- SDK source: `1dddb04cc423d07fcccedeedb0af2de2c2c6265a`.
- Original SDK: 4,040,076 bytes, SHA-256 `e32d199f3c0839e4e7af76863599ec01954271c812fc03d1dc4e5105b6c79443`.
- Original SDK SRI and independent active protocol pin: `vendor/mdbase-sdk-dev-1dddb04c.json`. The active protocol is the original `c280cd194ffd` packet (107,322 bytes), not the retained older protocol archives.
- `MdbaseConnect`, `MdbaseApplicationDeclaration` and `MdbaseApplicationEntry` come from `@mdbase-dev/sdk`.
- Test-only `createApplicationFixture` and `MemoryReplica` come from `@mdbase-dev/sdk/testing`; the production entry never imports testing.
- The live public `MdbaseConnect` singleton owns lifecycle, `application()` and `connection(id)`. `snapshot.selection` distinguishes a requested collection from an actually usable one; an unapproved request cannot borrow an old ready connection.
- Approval, access review and the chooser invoke SDK `approve()`, `reauthorize()` and `chooseAnother()` directly in the gesture stack, preserving the original caller signal. No app-side selection URL parser, popup callback, raw installation bootstrap or missing-runtime workaround remains.
- Records use the same public `connection.records`, original create mutation/UUID, receipt/readback and shared record sessions. Files use that client's identical public FilesApi.

The build verifies the immutable archives and every installed SDK dist member against its original archive. It consumer-bundles only the built public ESM entry, retains the original same-artifact Worker beside it and preserves the packaged native module directory. SDK4c contains the original canonical runtime/SQLite WASM and default-expiry LAB trust. Its packet metadata reports `native.available=true`; this means asset availability only, not browser/native readiness, application registration or LAB admission. LAB native consumer builds work with explicit build inputs and preserve the original Worker/WASM bytes; production trust remains unavailable. The runtime remains independently sourced at `fa49f3d0474a3c5961f3b9986052ead07abcc943` (3,555,291 bytes; SHA `9f90af73e1591cafe9c35bdd42f18ae49d5a91a0186e78695e841fecabcd833a`), qualified at pin commit `9935671f0f1f1fdfa3e9a6835bbff10bff3b34ef`. Its original native module includes `rt_app_setup_assess`; actual Core assessment and guarded configuration-only planning were verified without a runtime session or write. This does not prove durable adoption or pack application. Native source, pin commit and SDK source remain distinct. The SDK's normal module-relative Worker/WASM/SQLite layout is preserved, including its literal asset references; Journal adds no bundler workaround. It does not rebuild, repack, rewrite installed declarations, renew trust or inject callbacks. Native/SQLite assets are integrity-pinned, not separately signed. The normal SDK producer bundles its existing pinned protocol dependency, so a fresh install root and empty npm cache can resolve it without installed metadata or app-specific dependency workarounds. The active original protocol archive remains byte-identical. This packet has `vendorWarnings=[]`: the unused historical protocol member is absent. The older packet and its packet-specific warning remain unchanged in retained provenance; no exception is carried forward.

The current cut adds SDK-owned lazy Worker startup and pairing only from a sign-in gesture, native-return opening and refused/expired sign-in recovery. SDK refusal copy is unchanged; Sign in remains enabled while authorizing and invokes `approve()` from the click. Journal supplies no pairing or renewal engine.

`npm run build` requires the environment and exact origin, which also becomes the manifest homepage; the application ID defaults to the manifest's. See [README](../README.md). `npm run build:local` is an explicit writing-only build with no application constructor. Registration/native admission and deployment remain separate. The earlier SDK archive and provenance remain unchanged.

`npm run verify` checks strict declarations with `exactOptionalPropertyTypes=true`, `noUncheckedIndexedAccess=true`, `skipLibCheck=false`, public fixture/actual SDK records and files, browser-asset byte pins, and the writing-only build. Fixtures prove controlled app behavior, not physical popup/native lifecycle or real catalog readiness. The baseline prototype tests were replaced with typed tests of the new surface, not kept as a second app auth/data engine.

Earlier prototype drafts remain in their original storage namespace and are counted in settings. They are not automatically replayed without their original native identities. Failed local persistence never authorizes capture or clearing RAM text; uncertain native creation only checks the original receipt and record.
