---
kind: mdbase.type
name: journal-entry
version: 2
description: A note written in Journal.
match:
  where:
    type: journal-entry
schema:
  dialect: json-schema-2020-12
  value:
    $schema: https://json-schema.org/draft/2020-12/schema
    title: Journal entry
    type: object
    required: [created]
    properties:
      created:
        type: string
        format: date-time
        description: When the page was opened, with the writer's local UTC offset. Set by Journal.
      modified:
        type: string
        format: date-time
        description: When the entry last changed. Maintained by this type's lifecycle rules.
    additionalProperties: true
lifecycle:
  on_create:
    set:
      modified: { now: true }
  on_update:
    set:
      modified: { now: true }
implements:
  - contract: journal.entry
    version: 0.1.0
    fields:
      created: created
---

# Journal entry

One note per page written in Journal. Journal sets `created` when the note is
first saved and writes the text as the note's body. It never reads entries back,
so open them in Editor or any other app.

Journal names this type explicitly when it creates a note, so the collection
records it under its own type key (`type` by default). The schema does not
require that key; the `match` rule only recognises notes written by hand with
`type: journal-entry`.

This type belongs to your collection. Journal installed it once and will not
change it again, so customise it freely.

## Add fields that fill themselves in

Lifecycle rules run whenever an entry is created or saved. To tag every new
entry, add a `tags` field to the schema and a rule under `on_create`:

```yaml
lifecycle:
  on_create:
    set:
      modified: { now: true }
      tags: { literal: [journal] }
```

Other providers include `{ today: true }` for a plain date and `{ uuid: true }`
for a stable identifier. Rules under `on_update` run on every save; `modified`
is kept current that way.

## Rename fields

Journal relies only on the `journal.entry` contract, not on these field names.
To store the time as `date` instead, rename the property in the schema and
update the mapping:

```yaml
implements:
  - contract: journal.entry
    version: 0.1.0
    fields:
      created: date
```

Keep exactly one type implementing `journal.entry`. With two, Journal cannot
tell which one new entries should use.
